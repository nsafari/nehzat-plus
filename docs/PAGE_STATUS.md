# وضعیت نهایی صفحات — Nehzat Plus (Lesson Planner)

**تاریخ:** 2026-07-20
**مبنا:** بازخوانی واقعی کد (کنترلرهای بک‌اند + کامپوننت‌های فرانت‌اند + `assessment-panel`)
**توجه:** نقد ۵ زاویه‌ای قرار بود با ۵ کارگر موازی (hyperplan) انجام شود، اما به دلیل عدم دسترسی محیط به مدل‌های مورد نیاز (`claude-opus-4-7`/`gpt-5.5`/`gemini-3.1-pro`) اجرا نشد. نقدها توسط هماهنگ‌کننده (Prometheus) بر اساس همان زوایا و کد واقعی نوشته شده است.

## ۱. وضعیت فعلی هر صفحه (واقعی، از روی فایل‌ها)

| صفحه | فایل‌ها | خطوط تقریبی | وضعیت |
|------|---------|-------------|--------|
| `coach` | ۲ ts (component + routes) | ~۷۳ | استاب: هدر + پیام "نسخه بعدی" |
| `parent` | ۲ ts | ~۷۳ | استاب خالی (فقط component + routes) |
| `branch-manager` | ۲ ts | ~۷۳ | استاب خالی |
| `evaluator` | ۲ ts (routes شامل AssessmentPanel) | ~۷۳ | نمایش `assessment-panel` (آماده‌ترین استاب) |
| `headquarters` | ۲ ts | ~۷۳ | استاب خالی |
| `dashboard` | ۱ html + ۳ ts | ~۵۲۲ | نسبتاً کامل (shell + assessment-taker + training-steps) |
| `admin` | ۱ html + ۳ ts | ~۲۲۳۳ | بزرگ‌ترین/پیچیده‌ترین (landmine) |

**نتیجه:** ۵ صفحه (coach/parent/branch-manager/evaluator/headquarters) هنوز استاب هستند و به سرعت قابل توسعه‌اند. dashboard نیمه‌کاره و admin نیازمند بازسازی.

## ۲. نقد ۵ زاویه‌ای پلن (ضمیمه برای توسعه‌دهندگان)

### 🔴 زاویه ۱ — معمار سیستم (ریسک تنگنا)
1. **مشکل:** انتگریتور مسئول تقسیم `AdminController.cs` (~۱۰۳۰+ خط) است اما همه ۵ Dev در هفته ۱ موازی شروع می‌کنند. اگر ری‌فکتوری routeها را تغییر دهد، Devها بلوکه می‌شوند.
   - **پیشنهاد:** انتگریتور ابتدا زیر-کنترلرها را بسازد و PR جداگانه ادغام کند، *قبل* از شروع موازی بقیه.
2. **مشکل:** ترتیب موازی فرض می‌کند routeها ثابت می‌مانند.
   - **پیشنهاد:** قرارداد route ثابت (مثلاً `/api/admin/*`) قبل از تخصیص نهایی بنویسید.
3. **مشکل:** جداسازی لایه‌های Clean Architecture در صورت عجله نقض می‌شود (Dev ممکن است منطق را در کنترلر بنویسد).
   - **پیشنهاد:** در DoD چک شود که سرویس در `Infrastructure/Services` باشد نه کنترلر.

### 🔴 زاویه ۲ — توسعه‌دهنده فرانت‌اند (الگوی تکرارپذیر)
1. **مشکل:** `coach.component.ts` الگوی استاب ضعیفی است (inline template، بدون OnPush، بدون جداسازی html).
   - **پیشنهاد:** قبل از شروع موازی، یک **تمپلیت استاندارد** (component + html جدا + OnPush + ChangeDetection) آماده و در `shared/` یا docs قرار دهید؛ بقیه از آن کپی کنند.
2. **مشکل:** جداسازی template به `*.html` درست توصیه شده اما اجباری نشده.
   - **پیشنهاد:** در DoD الزام شود.
3. **مشکل:** `assessment-panel` بین evaluator و dashboard به اشتراک گذاشته می‌شود بدون قرارداد ورودی/خروجی.
   - **پیشنهاد:** از `@Input() mode` یا دو کامپوننت (`assessment-creator` / `assessment-viewer`) استفاده شود.

### 🔴 زاویه ۳ — امنیت (دسترسی صفحات)
1. **مشکل:** DoD فقط `roleGuard` را چک می‌کند، نه دسترسی سطح داده.
   - **پیشنهاد:** تست شود که والد فقط فرزند خودش را ببیند (نشت داده بین نقش‌ها).
2. **مشکل:** `headquarters` خلاصه کل سیستم را می‌بیند — اگر `roleGuard('headquarters')` اشتباه اعمال شود، ریسک افشای گسترده.
   - **پیشنهاد:** در DoD تست دسترسی منفی (Negative test) اضافه شود.
3. **مشکل:** refresh token در `localStorage` (طبق AGENTS.md) در برابر XSS آسیب‌پذیر است.
   - **پیشنهاد:** در مستندات امنیتی ثبت شود (خارج از scope این پلن اما هشدار داده شود).

### 🔴 زاویه ۴ — بک‌اند/داده (تبعات parentId)
1. **مشکل:** پلن می‌گوید parent از `getParentStudents(parentId)` استفاده کند، اما `parentId` از `getCurrentUser()` قابل استخراج نیست مگر رابطه `Parent↔User` در مدل‌ها باشد.
   - **پیشنهاد:** انتگریتور متد `getCurrentParentId()` یا mapping در API اضافه کند *قبل* از شروع Dev B، وگرنه Dev B مجبور می‌شود `core/models` (فایل قفل‌شده) را تغییر دهد → تداخل.
2. **مشکل:** رابطه Parent-Student احتمالاً نیاز به junction table دارد (طبق landmineهای AGENTS.md: CSV جایگزین نشده).
   - **پیشنهاد:** قبل از شروع، مدل داده نهایی تایید شود.
3. **مشکل:** متدهای API در interface هستند اما برخی ممکن است در سرویس پیاده‌سازی نشده باشند.
   - **پیشنهاد:** لیست متدهای واقعی پیاده‌شده (از کنترلرها استخراج شد) در پلن موجود است — Devها به همان لیست اتکا کنند.

### 🔴 زاویه ۵ — هماهنگ‌کننده (ریسک landmine جدید)
1. **مشکل:** همان اشتباه `admin` (فایل غول‌آسا) در `assessment-panel` تکرار می‌شود چون evaluator و dashboard هر دو می‌خواهند از آن استفاده کنند با نیازهای متفاوت.
   - **پیشنهاد:** قبل از شروع evaluator/dashboard، `assessment-panel` به دو کامپوننت تقسیم شود یا با `@Input()` mode شده باشد.
2. **مشکل:** مرزبندی "فقط پوشه خودت" وقتی کامپوننت مشترک در میان است، صفر نیست.
   - **پیشنهاد:** مالکیت `assessment-panel` را به یک نفر (انتگریتور یا Dev مسئول shared) بسپارید.
3. **مشکل:** DoD برای جلوگیری از تداخل PR کافی نیست.
   - **پیشنهاد:** path-filter در PR (فقط `features/<role>/`) اجباری شود.

## ۵. Definition of Done (بهبودیافته)

هر صفحه وقتی «تمام» است که:
- [ ] فایل `*.component.html` جداگانه دارد (نه inline)
- [ ] از `ChangeDetectionStrategy.OnPush` استفاده می‌کند
- [ ] حداقل ۲ متد API واقعی (تأییدشده از لیست کنترلرها) را فراخوانی می‌کند
- [ ] نقش با `authService.hasRole()` / `roleGuard` چک می‌شود
- [ ] **تست دسترسی منفی:** نقش دیگر به داده دسترسی ندارد
- [ ] استایل فقط `--lp-*`
- [ ] `ng test` سبز است
- [ ] PR فقط پوشه ماژول خودش را لمس می‌کند (path-filter)
